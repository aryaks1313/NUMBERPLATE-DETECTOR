HOW TO USE THIS GUIDE
This guide follows the current project files. It explains imports, classes, functions, and main logic in simple English. It explains what the code does rather than repeating every punctuation mark. The source code is the final authority if a later code change makes this guide out of date.

IMPORTANT CURRENT LIMITS
The measured 32.6 FPS result is a warm detector-only benchmark on a still image. It does not measure camera capture, OCR, database search, and browser update together. The current uploaded-video processor samples about six frames per second. The full application has not been verified at 24 FPS. The ten unseen plate accuracy check has also not been completed, so the project must not claim 8 out of 10 yet.

1. THE WHOLE PROJECT IN ONE MINUTE

A camera or video provides images. OpenCV reads them. A YOLO model finds the plate rectangle. The program crops that rectangle. Tesseract OCR tries to read its letters and numbers. Plate helper functions clean and validate the text. The booking service searches today's booking records. FastAPI sends the result to the browser. The browser shows a plate image and, if found, the customer, appointment and advisor.

The path is:
Camera/video frame -> YOLO plate box -> plate crop -> OCR characters -> normalized Indian registration -> today's booking lookup -> saved detection and dashboard notification (for a database booking) -> browser result.

A plate can fail at more than one point. The model may not find it. OCR may read a wrong character. The plate may be valid but have no booking for today. These are different outcomes and should be checked separately.

import_bookings_csv(file, admin, db)
1. Requires admin and a .csv file. Excel .xlsx is not accepted directly.
2. Reads at most 5 MB plus one byte to detect an oversized upload.
3. Decodes UTF-8 with BOM support, covering common Excel CSV exports.
4. Reads the first row as column headings.
5. Checks required headings and requires advisor_id or advisor_name.
6. Loads active advisors and creates lookup maps for ID and name.
7. Goes through rows starting at row 2 because row 1 is the header.
8. Cleans plate text, checks date, time, required details and advisor.
9. Skips duplicate vehicle/date pairs already in the upload or database.
10. Collects row errors. If any row is invalid, returns an error without applying the batch.
11. Otherwise adds all new bookings and commits once.
12. Returns counts for imported and duplicate rows skipped.

advisor_dashboard(user, db) calculates the advisor's booking count, notification count, unread count, matched vehicle detections and latest ten notifications.

advisor_notifications(user, db) returns notifications belonging to the signed-in advisor, newest first.

update_notification(notification_id, data, user, db)
1. Finds the notification.
2. Checks the current user owns it, unless the user is admin.
3. If status was supplied, only accepts 'created' or 'completed'.
4. Completing it also marks it read.
5. If is_read was supplied, updates read/unread.
6. Saves the changes.

admin_dashboard(admin, db) counts advisors, bookings, detections and matched detections. It also returns camera monitor status.

process_frame(frame, source, persist) - the recognition pipeline
This function is used by live camera and video. It creates its own database session and then:
1. Calls plate_detector.detect(frame).
2. If it finds nothing, returns status 'no_plate'. No normal plate result is created.
3. If multiple boxes exist, picks the one with highest detector confidence.
4. Calls read_plate(crop) for OCR.
5. Calls normalize_plate to remove spaces/punctuation and make letters uppercase.
6. Builds a common result with text, display form, confidence, box and source.
7. Returns 'invalid_plate' if the text is not a plausible Indian registration.
8. Calls find_booking to search today's bookings.
9. If a unique fuzzy match supplied the booking's true plate, updates the displayed registration.
10. Returns 'unmatched' if the valid plate has no booking.
11. A sample CSV booking has no database ID. The function returns customer/advisor details and can save an image, but does not create a database foreign-key row.
12. If persist=False, as used for video, returns match details without writing detection/notification records for every sampled frame.
13. For a database booking, checks if the same plate and booking were detected in the last ten minutes. If yes, returns 'duplicate'.
14. Otherwise saves a frame image, creates a Detection row, creates an in-app dashboard Notification for the assigned advisor, commits both and returns the match.
15. On an exception it rolls back and re-raises the error. finally always closes the database session.

process_camera_frame(frame) calls process_frame with source='live'. It adapts the shared processing function for CameraMonitor.

upload_video(video, admin)
1. Allows MP4, AVI, MOV and MKV extensions.
2. Saves the upload in chunks and stops above 200 MB.
3. Opens it with OpenCV. If it cannot open, removes the bad file and returns an error.
4. Reads video FPS and frame count to estimate duration.
5. Selects frames at about six samples per second.
6. Calls process_frame with persist=False for every sampled frame.
7. Ignores no-plate, invalid-plate and other non-readable statuses.
8. Keeps one best-confidence image/result for each unique valid plate.
9. If a later frame has a booking match and an earlier frame did not, it carries the booking details into the retained result.
10. Saves the best frame for each plate and returns counts, frame number, confidence and status.
11. Releases video capture in finally so the file is closed even after an error.

get_camera_source() reads CAMERA_SOURCE. A digits-only value becomes a camera index, such as integer 0. Other values stay as a URL or source string.

start_monitor(admin) reads camera source and optional frame delay, then starts camera_monitor. Admin-only.
stop_monitor(admin) tells the monitor to stop and release the camera. Admin-only.
monitor_status(user) returns current camera status to a signed-in user.
admin_notifications(admin, db) returns up to 100 newest notifications across advisors.

2.6 app/security/auth.py - passwords and access control

Imports: os reads environment values if needed. hmac safely compares hashes. hashlib calculates PBKDF2 password hashes. secrets creates random salts. Request reads session. HTTPException returns access errors. Depends connects FastAPI dependencies. Session and get_db access the database. Advisor is the advisor table.

hash_password(password)
1. Creates a random salt.
2. Uses PBKDF2-HMAC with SHA-256 and 310,000 rounds to make a password hash.
3. Returns salt and hash joined with '$'. The original password is not stored here.

verify_password(password, stored_hash)
1. Splits the saved salt and expected hash.
2. Repeats the same PBKDF2 calculation for the entered password.
3. Uses hmac.compare_digest to compare results.
4. Returns False if the stored value is malformed.

get_current_user(request, db)
1. Reads user details from the session.
2. Returns 401 if no session exists.
3. Returns a small identity if role is admin.
4. For an advisor, finds the database row and requires is_active=True.
5. Clears the session and returns 401 if the advisor is missing/inactive.
6. Rejects unknown roles.

require_admin(user) checks role is admin or returns 403.
require_advisor(user) checks role is advisor or returns 403.

2.7 app/services/detector.py - finding the plate box

Imports: Path and os find model path/CPU count. cv2 rotates images. torch controls PyTorch threads. YOLO loads the trained model. settings provides detector configuration.
BASE_DIR calculates the project root. torch.set_num_threads limits inference threads to avoid CPU oversubscription.

PlateDetector class
__init__ sets model=None and resolves model path. A relative path becomes project-root-relative.
load_model() returns an existing loaded model. Otherwise it checks the file, raises a clear missing-file error, loads YOLO once and returns it.
apply_roi(image) converts relative ROI values into pixel coordinates, keeps them inside the image, crops the region and returns the crop plus its offset. Offsets are needed to map detection coordinates back to the full frame.

detect(image)
1. Loads YOLO and crops the ROI.
2. Uses a minimum inference size of 224 pixels because smaller tested sizes lost plates.
3. Uses a detector threshold no higher than 0.15 to help find dim/dirty plates. OCR validation filters bad text later.
4. Tries original ROI, 90-degree counter-clockwise and clockwise rotations.
5. Reads predicted box coordinates and confidence.
6. Converts box coordinates back if image was rotated.
7. Adds the ROI offset and clamps coordinates to the original image.
8. Crops the box and returns box, confidence and crop.
9. Stops after the first orientation that yields detections.

plate_detector = PlateDetector() creates the shared detector object. The model loads the first time detection is requested.

2.8 app/services/ocr.py - reading plate pixels

Imports: Path checks Windows Tesseract locations. cv2 prepares image variants. pytesseract calls Tesseract. settings provides an optional executable path. clean_indian_plate validates and repairs OCR text.

_configure_tesseract() uses TESSERACT_CMD if configured. Otherwise checks common Windows install folders and uses the first executable found.

preprocess_plate(image)
1. Returns no variants for an empty crop.
2. Converts color image to grayscale.
3. Enlarges a small crop with cubic interpolation.
4. Applies bilateral denoising while preserving edges.
5. Uses CLAHE to improve local contrast.
6. Applies adaptive thresholding so text stands out.
7. Returns enlarged, enhanced, thresholded and inverted versions.

read_plate(image)
1. Returns empty text if no crop exists.
2. Rotates a tall crop clockwise so a plate is horizontal.
3. Trims a small border from a wide plate crop.
4. Restricts Tesseract to letters A-Z and digits 0-9.
5. Reads each preprocessed version with OCR modes 8 and 7 for the first version and mode 8 for others.
6. Cleans each OCR answer with clean_indian_plate.
7. Returns blank if no answer resembles a valid Indian plate.
8. Otherwise prefers 9-10 character registrations and longer valid text.

PSM means page segmentation mode. It tells OCR what kind of text arrangement it should expect.

2.9 app/services/plate_utils.py - cleaning registration text

Imports: re supports regular expressions.
_INDIAN_PLATE describes two state letters, one or two RTO digits, one to three series letters and four final digits.
_DIGIT_FIX maps letters often mistaken for digits, such as O to 0 or I to 1.
_LETTER_FIX maps digits often mistaken for letters, such as 0 to O or 8 to B.

normalize_plate(value) uppercases text and removes everything except A-Z and 0-9. 'kl 07 ab-1234' becomes 'KL07AB1234'.

clean_indian_plate(value)
1. Normalizes the text.
2. Creates the unchanged candidate.
3. For the common two-digit RTO format, fixes digit positions and letter positions separately.
4. For a one-digit RTO variation, uses the corresponding character positions.
5. Returns the first candidate matching the pattern, or an empty string.

format_indian_plate(value) cleans the text and adds spaces between state, RTO, series and final digits. If invalid, it returns normalized text for display.
is_plausible_indian_plate(value) returns True only if cleanup validates it.

2.10 app/services/booking_service.py - matching a registration

Imports: csv reads fallback rows. date/datetime parse dates. Path locates the sample file. SimpleNamespace makes a lightweight booking-like object without saving a database row. ZoneInfo sets India time. Session, Advisor and Booking access database records. Plate helpers normalize text.

INDIA_TZ is Asia/Kolkata. BASE_DIR locates the project. SAMPLE_BOOKINGS_PATH points to sample_bookings.csv.

get_indian_today() returns today's date in India time.

_one_edit_apart(first, second) compares strings character by character. It allows exactly one insertion, deletion or substitution. More than one edit returns False. The caller accepts a fuzzy match only if there is one unique candidate.

_csv_bookings(db, today)
1. Returns empty list if the sample CSV is missing.
2. Opens UTF-8 CSV with BOM support.
3. Keeps rows whose date equals today. This fallback parser expects YYYY-MM-DD.
4. Looks up advisor by ID to get the current name when possible.
5. Uses advisor name from CSV or a generic label if no database advisor exists.
6. Creates lightweight booking-shaped objects and returns them.

find_booking(db, plate_number)
1. Cleans/normalizes recognized text.
2. Returns no match for blank text.
3. Loads today's database bookings.
4. Looks for exact normalized plate first.
5. If exact lookup fails, collects plates one edit away.
6. Accepts fuzzy match only if there is exactly one candidate.
7. If there are ambiguous candidates, does not guess.
8. If no database match, checks exact and unique fuzzy match in today's sample CSV.
9. Returns a database booking, CSV-backed object or None.

2.11 app/services/monitor.py - live camera worker

Imports: threading runs work in a separate worker. time provides waits. Path builds folders. cv2 opens camera and writes preview.

CameraMonitor class
__init__ creates running flag, thread, stop event, lock, error field, frame counter, last result and preview URL. It creates uploads/monitor and selects latest.jpg.

start(camera_source, process_frame, interval)
1. Locks shared state to avoid two concurrent starts.
2. Returns an already-running message if needed.
3. Clears stop signal and resets old status.
4. Sets running=True.
5. Starts a daemon thread that runs _run with camera source, processor and delay.

_run(camera_source, process_frame, interval)
1. Opens camera with OpenCV, or records an error if it cannot.
2. Reads frames until stop_event is set.
3. If read fails, stores an error and waits one second before retrying.
4. Calls the shared recognition function.
5. Copies frame, draws a rectangle if a box exists, adds status text and saves latest.jpg.
6. Under a lock, updates frame count, last result, preview URL and error state.
7. Records processing exceptions as last_error.
8. Waits interval seconds if configured.
9. Always releases the camera and marks stopped in finally.

stop() sets the stop event, waits up to five seconds for worker exit, marks stopped and returns status.
status() copies current values under a lock and returns them to the API.
camera_monitor = CameraMonitor() creates the shared monitor.

app/__init__.py and app/services/__init__.py are package marker files. They let Python import modules from these folders; they contain no recognition algorithm.

renderNotifications(notifications) shows notification content plus read/unread and completed/open labels. It adds buttons to toggle read and complete state.
updateNotification(notificationId, changes) PATCHes the change to /api/notifications/{id}, then reloads notification/dashboard data. It displays errors in an alert.

Refresh button handlers call loadBookings or loadNotifications.
startBackgroundRefresh() clears an old timer and refreshes the dashboard every five seconds. It refreshes the currently visible bookings, notifications or admin camera page as needed.
Logout handler POSTs /api/logout and navigates to login.
DOMContentLoaded handler starts initializeApp after HTML elements exist.

3.4 static/style.css - visual appearance
CSS does not detect plates. It controls colors, fonts, layout, spacing, tables, forms and responsive behavior. :root stores reusable color variables. Body and button/input rules set defaults. Sidebar/topbar/page-section rules arrange the dashboard. Table/form classes style booking content. Status-pill variants show colored states. Camera and video classes size previews and thumbnails. The @media rule changes the layout on narrow phone screens.

5. PYTHON WORDS IN SIMPLE ENGLISH

Import: use code from another package or project file.
Class: a description/template for creating related objects, such as Advisor.
Object: one working instance made from a class.
Function: named instructions that can be called.
Parameter: information passed into a function.
Return: the answer a function sends back.
Decorator such as @app.get: tells FastAPI which URL and HTTP method call a function.
Database session: a short-lived connection used to read/write rows.
Exception: an error signal that interrupts normal work until handled.
try/except/finally: try the work, handle errors, always perform cleanup.
JSON: text format used to send named values between browser and server.
HTTP 200: request worked. 400: bad request data. 401: login required/invalid. 403: signed-in role is not allowed. 404: record not found. 413: upload too large.

6. HOW TO TRACE A RESULT

If nothing is detected, inspect detector.detect: did YOLO return boxes? Check the camera image and camera source.
If a box exists but no text, inspect the crop and read_plate preprocessing/Tesseract path.
If text exists but is invalid, check clean_indian_plate and its registration pattern.
If the plate is valid but unmatched, check find_booking, today's date in India and booking vehicle_number.
If the API result is correct but the screen is wrong, inspect the static/app.js rendering function and matching IDs in static/index.html.

If a match came from the sample CSV, process_frame returns it for the screen but does not create database Detection or Notification rows. Database bookings can create those records when persist=True and the duplicate-window check passes.

7. COMMON PROBLEMS AND SIMPLE FIXES

CSV says Invalid isoformat string: '23-11-2026'
Use the CSV import screen with its current date parser, which accepts DD-MM-YYYY. For sample_bookings.csv fallback, use YYYY-MM-DD. Check headings against the downloaded template.

Cannot read properties of null (reading 'reset')
JavaScript tried to reset an HTML form that was not present. Check the element ID and check the form exists before reset. Reload the latest app.js after a fix.

Camera opens but shows no plate
An open camera only proves OpenCV can read images. Aim it at a vehicle plate. Use the correct camera source and enough light, focus and plate size. A room image has no plate, so no plate result is expected.

Video shows no result
Use a supported video and keep the plate visible in several frames. The system samples about six frames per second. Check orientation, model path and lighting. A valid Indian plate format is required for a result card.

Wrong OCR characters
The code fixes common confusions by character position, but cannot guarantee every dirty/angled plate. Improve focus/light and collect gate examples for future tuning.

Booking does not match
Check the plate, today's date in India, active advisor and whether the booking is in the database or correct fallback CSV. Exact match is preferred. Fuzzy match is accepted only if there is one unique candidate.

YOLO model missing
Confirm models/best.pt exists and the configured model path points to it.

Tesseract executable missing
Install Tesseract or set its path in the private TESSERACT_CMD setting, then restart the server.

Database cannot connect
Check database service and private connection setting. Do not paste the connection string into chat or public source files.

Video upload rejected
Use MP4, AVI, MOV or MKV, below 200 MB. Check that the video plays normally before upload.

401 or 403
Sign in again for 401. For 403, use the correct account role or ask an admin to activate the advisor.

Notification buttons do nothing
Refresh, verify sign-in and check browser/API errors. The server supports read/unread and created/completed. Completed notifications are marked read automatically.

8. DEMO EXPLANATION FOR THE EVALUATOR

Say: 'I will upload a prepared gate video. The application samples frames, detects plate areas, reads text, cleans it and looks for today's booking. The screen shows recognized plate results, with one best frame for each plate.'

When the sample match appears, say: 'This is the detected plate. The application found a matching sample booking, so it displays the customer, appointment and advisor.'

When a plate does not match, say: 'The plate was read, but there is no booking for it today.'

When no plate appears, say: 'There was no readable plate in this scene, so the application does not add a recognition result.'

If asked about speed, say: 'The 32.6 FPS figure is for the warmed detector on a still image. Video processing currently samples about six frames each second. The full application has not yet been measured at 24 FPS.'

If asked about accuracy, say: 'The application has not yet been formally tested on ten unseen plate examples. I will record the exact result after that test. I will not claim the 8 out of 10 target until measured.'

9. SHORT SUMMARY TO MEMORIZE

OpenCV gets the frame. YOLO finds the plate. Tesseract reads it. Plate utilities clean it. Booking service searches for today's appointment. FastAPI sends the result. JavaScript displays it. The database stores advisors, bookings, detections and notifications.

This guide covers all active project files, imports, classes, functions, route handlers and main logic in the current source. It cannot explain the internal learned values in best.pt or generated uploads as source code because those are binary/image/video data.
